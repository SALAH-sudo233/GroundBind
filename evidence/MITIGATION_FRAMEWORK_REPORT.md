# 定位复用与虚假定位的缓释框架：结构化核验

**日期**：2026-09-27
**对齐基准**：`V-SIGHT_v0.48_front4_en_main.pdf` §3.4 与 Table 4（Direct grounding）
**评测集**：**500-dev**（`refcocog_500_dev.semantic_strict.json`，500 图 × (1 正例 + 4 负例) = 2500 条），与论文 Table 4 所用评测集**逐图一致**（图像集合完全相同，500/500），13 个上游模型
**GPU 工作量**：验证器读数 32,500 + 65,000 行、对立词核验 28,064 次、跨 run 重打 5,940 次，**error = 0**

---

## 1. 这个框架要接住论文的哪个问题

论文的诊断结论是：**定位成功与拒绝无效指称是两种能力**。benchmark 把失败拆成两个可分别测量的量：

- **FGR（false grounding rate）**：不成立的表达仍然拿到了框。分母是该类型的全部 500 个负例（含拒绝），四类合计 2000。
- **CBR（conditional box reuse）**：在**正例已被正确定位**（IoU ≥ 0.5）的图像组里，不成立的表达拿到了与正例**几乎相同**的框（IoU ≥ 0.8）。分母 `n_c` 是该模型正确定位的正例数。

论文 Table 4 的关键观察：**定位最成功的模型反而把那些区域留给了不成立的属性和关系**（group B）。FGR 高只说明"乱出框"，CBR 高说明的是"**把看对的区域复用给了看错的话**"——这是本框架的直接靶子。

论文诊断到此为止，把主方法留空（`sections/6_method.tex` 是未导入的占位）。本报告要填的正是这一格：**在不重训上游模型、不改其权重的前提下，把 FGR 和 CBR 同时压下来，并且不牺牲正例定位。**

两条指标必须**同口径同时报**，否则任一单独都能被作弊：只要多拒绝，FGR 和 CBR 都会下降，代价是正例也被拒。所以下面每张表都带 `posKeep` 与 `pos_mIoU` 两列。

## 2. 框架：三段结构化核验

框架不改上游模型，只在其输出后面加一道**只读的核验**。名字是**结构化核验**（structured verification），不是"自主推理系统"——它的每一步都是确定性模板或一次前向打分，没有自由生成的推理链。

```
上游 VLM ──→ (表达, 框) ──→ ① 单臂核验 ──→ keep / reject
                               │
                               └─ 关系类且保留 ──→ ② 对立词探针 ──→ ③ 比较门 ──→ 改判
```

### ① 核验（对所有 2500 条）

把上游返回的框连同表达交给两个验证器，各读出一个标量分数：JEV 读最后一个 prompt 位的隐状态（温度标定后），OMNI 读红框叠图下 `true`/`false` 的 logit 差。两个 `z0` 一并作为特征。

高于阈值则保留，否则拒绝（框作废，等价于模型输出空结果）。

### ② 对立词探针（只在关系类触发）

关系类负例的错误模式是**谓词被换掉**（`the chair behind the person` → `next to`）。对每个关系表达，用**确定性模板**枚举审计过的对立谓词（`behind` / `in front of` / `next to` / `above` / `below` ...），构造出与原表达只差谓词的对立表达，让**每个验证器各自**给**同一个框**打分，得到该验证器自己的 `z_rival`。

判据是每个验证器内部的**差值**：

```
gap_JEV  = max(z_rival^JEV)  − z0^JEV
gap_OMNI = max(z_rival^OMNI) − z0^OMNI
```

若 gap > 0，说明在该验证器眼里，这个框更像是在支持一个**别的**关系——即它复用了区域但关系是错的。这正是 CBR 想抓的失败。两个 `gap` 与两个 `z0` 共四个特征进入判决头。

> **构造约束**：`z_rival` 与 `z0` 必须来自**同一个验证器、同一个分数定义**。两个不同验证器的分数在同一批行上 Pearson r 仅 0.32，其差值不承载信息。本报告所有 gap 均为同打分器内差值，并经尺度一致性核验（对立词 mean −3.554/sd 4.029 vs 同行 `z0` −3.035/sd 4.330）。

### ③ 比较门（gate）

只有**关系类且已被 ① 保留**的行才允许被 ② 改判；其余行**逐位沿用 ① 的判决**。

这带来一个可验收的性质：**object / co-occurrence / attribute 三类的 CBR 在 A2 与 B1 之间必须逐位相同（0.00pp，0 行变动）**。这是本框架的加法性自检，下表可见其成立。

### 臂的定义

| 臂 | 含义 |
|---|---|
| **B0** | 缓释前，上游模型原样输出（= 论文 Table 4 的那一列） |
| **B1** | 只加 ① 核验（两个 `z0`，无探针） |
| **A2** | ① + ② + ③ 完整框架 |

## 3. 验证器：JEV + OMNI 双读数

核验由**两个互补的验证器**共同完成，二者读同一张图、同一个上游框：

| 验证器 | 规模 | 训练量 | 读数 |
|---|---|---|---|
| **JEV** | Qwen3.5-2B + 全层 LoRA r=8（α=16，仅 attention 投影）+ `(1, 2048)` 标量头 + 温度标量 | **1000 步**单卡，`bs=4 × accum=4`，`lr 5e-5`／`head_lr 1e-4`，**可训练参数 2,506,752 / 2.22B = 0.113%** | 最后一个 prompt 位隐状态 → 标量头 → 温度缩放，一次前向、不生成 token |
| **OMNI** | OmniVerifier-7B（Apache-2.0） | **零训练**，权重直接使用 | 红框叠图 + `true`/`false` 的 logit 差 |

JEV 的训练目标只有一个二值标签（KEEP / REJECT），损失 `NLL + 0.1 × Brier`。Brier 是严格适当评分规则，在训练中即惩罚过度自信，使输出概率可用于阈值扫描：**58.2% 的预测概率落在 0.05–0.95 区间**。标定后 ECE 0.0305 → 0.0114、NLL 0.1525 → 0.1197（512 行留出片）。

**融合方式**：两个验证器各自给出 `z0` 与 `gap = max(z_rival) − z0`，共四个特征，由拟合的头决定权重。**每个 `gap` 都是该验证器自己的两个读数之差**，不存在跨打分器相减。

**整个框架只有 0.113% 的参数被训练**（JEV 的 2.5M），OMNI 不训练，上游模型权重不动。

**数据隔离已核验**：验证器在 2000 图像训练池（16,000 行）上训练，温度在该池的 512 行留出片上标定（ECE 0.0305 → 0.0114，NLL 0.1525 → 0.1197）。训练池与论文评测集**按 COCO 图像名核对，重叠 = 0**（2000 训练图 vs 探针覆盖的 351 评测图）。论文的 500 图评测集只在评测时被读取，训练与标定都不接触它。

> 训练池的标签来自 benchmark 构造流程本身（表达与区域的支持关系已知），**不需要新增人工标注**。

### 设计依据：分数必须连续可标定

在同一个 2B 底座上，我们对比了两种读数形态：本框架的连续标量头（58.2% 的概率落在 0.05–0.95），以及一个输出二值决定、置信度饱和在 {0,1} 的判决器。对立词探针在前者上给出 relation FGR **−13.77pp（13/13 模型）**，在后者上 −0.32pp（不显著，3/13）。

`gap = max(z_rival) − z0` 是一个差值判据，只有当分数在中间区间有分辨力时它才承载信息。**这决定了验证器的读数形态选择：连续、可标定的标量分数，而非二值判决。**

## 4. 评测口径（与论文严格一致）

| 项 | 取值 |
|---|---|
| CBR 定义 | θ=0.5（正例正确）、τ=0.8（框相似），空/无效框 IoU=0，含拒绝的配对负例**全部留在**类型分母，`c_i=0` 整组移出 |
| FGR 分母 | 每类 500，四类合计 2000（拒绝算作未出框，不移出分母） |
| 正例侧 | `posKeep`、`pos_mIoU` 分母均为 500（被拒或未出框记 0，从不剔除） |
| 合格集 | `c_i` 与正例参考框在**缓释前冻结** |
| 阈值 | **交叉拟合**：fold A 的行用 fold-B 拟合的阈值判决，fold B 的行用 fold-A 的——没有任何一行被自己拟合出的阈值评价 |
| 分折 | `md5(图像名) % 2`，**图像级**（500-dev 的 500 张图） |
| 统计 | 模型级配对 bootstrap，13 模型等权，95% CI |

**口径对齐收据**：重算 B0 在全部 500 组上，**13/13 模型逐位复现论文 Table 4**（Direct grounding），均值 15.77/26.13/33.19/40.11 对论文 15.78/26.13/33.18/40.10，`sum(n_c) = 2423` 一致。

两项此前的分母错误已修正：

1. **CBR 分母**：旧缓释表只报 fold B（`n_c` 151 而非 275），因为阈值在 fold A 拟合。交叉拟合恢复论文的全 500 组分母，同时不破坏样本外纪律。
2. **FGR 分母（更严重）**：旧 FGR 表在 fold B 的行上统计，分母却写死全集 2000，**系统性减半**——B0 的 ALL-FGR 旧读数 31.18%，正确值 **59.20%**（fold B 平均只有 1064 个负例行，比值 1.90）。旧 FGR 数值一律作废，本报告全部为正确口径。

## 6. 结论

1. **口径已完全对齐且可复现**：13/13 模型逐位复现论文 Table 4；CBR 与 FGR 两处分母错误（后者曾使 FGR 减半）均已修正并交叉核验。
2. **框架同时降低 FGR 与 CBR**：relation FGR 77.09% → **39.62%**，relation CBR 40.1% → **18.7%**（低于缓释前的一半），ALL FGR 59.20% → **22.15%**，BOH 48.08% → 14.13%，ROH 70.33% → 30.16%。正例侧 `posKeep` 0.951 → 0.899、`pos_mIoU` 0.3738 → 0.3549。
3. **改善覆盖全部 13 个上游模型**：探针净效应 relation FGR −15.05pp、relation CBR −9.41pp，**两项均 13/13 模型下降**，95% CI 不含 0。
4. **JEV + OMNI 双读数优于任一单验证器**：相对仅 JEV，relation FGR −4.29pp、ALL FGR −1.85pp（13/13）、relation CBR −1.72pp；相对仅 OMNI，四项错误指标全部显著下降。互补性在不含探针的 B1 层面即成立（relation FGR −2.99pp 显著），说明两个验证器的读数本身携带不同信息。
5. **attribute CBR 上组合不如仅 JEV**：11.1% vs 9.9%，+1.19pp，CI[+0.60,+1.88]，13 个模型无一下降。加入 OMNI 的 `z0` 在属性类上移动了判决边界。若目标指标是 attribute CBR，仅 JEV 配置更优。
6. **训练量为 0.113% 的参数**：JEV 的 2.5M/2.22B、1000 步单卡；OMNI 零训练；上游模型权重不动；无新增人工标注。
7. **对立词探针是关键增量**：它把"这个框是否更像在支持另一个关系"变成同一验证器内的差值比较，在全部配置上显著降低关系类错误，且非关系三类的 CBR 差值恰为 0.000pp。
8. **可标定的连续分数是前提**：同一 2B 底座下，连续可扫的标量头给出 relation FGR −13.77pp（13/13），输出二值判决、置信度饱和在 {0,1} 的读数给出 −0.32pp（不显著，3/13）。
9. **关系类的残余错误率最高**：缓释后 relation CBR 18.7%、relation FGR 39.62%，而 object 分别为 1.8% 与 7.37%。关系类幻觉未被消除。

## 7. 限制

1. **只覆盖 direct grounding（DG）**。论文 Table 4 同时报告 joint grounding（JG），本框架的核验输出在 JG 上不存在。当前证据仅支持 DG 协议下的结论。
2. **探针只在关系类触发**。另三类的 CBR/FGR 变化逐位为 0，是 gate 的设计结果，不是"探针对它们也有效"。
3. **小 `n_c` 模型的 CBR 估计方差大**：UniVG-R1 的 `n_c` = 30、Visual-RFT = 26，其单点 CBR 变动一个样本即移动 3.3pp 和 3.8pp。
4. **谓词覆盖偏深度/垂直关系**。左右关系在本 benchmark 仅占 0.65%，`holding` 类谓词无审计过的对立词，探针对其无效。
5. **语言先验对照**：纯谓词对数似然比（不看图）在 GT 框关系类上 AUROC 0.8475，高于零训练单臂核验的 0.7441。本框架未使用该特征。当前证据不能区分关系类收益中有多少来自视觉核验、多少可由谓词分布先验解释。
6. **正例侧代价**：组合臂探针的 `posKeep` −0.004（CI 含 0）、`pos_mIoU` −0.005（显著）。相对仅 OMNI，组合的 `posKeep` 低 0.010、`pos_mIoU` 低 0.007（均显著）。
6b. **组合的推理成本是单线的两倍**：每个被核验的行需要 JEV 与 OMNI 各一次前向，被探针覆盖的行再各加一次。仅 JEV 配置的 relation CBR 为 20.4%（组合 18.7%），attribute CBR 反而更低。
6c. **attribute CBR 上组合劣于仅 JEV**（+1.19pp，0/13 下降）。当前证据不支持"组合在所有类型上更优"的结论。
7. **交叉拟合与单折冻结阈值是两种协议**，数字不可混排。单折结果见 `cbr_3lines.txt` 第 [3] 节。
8. 训练标签来自 benchmark 构造流程，**与评测数据同源于一套生成规则**（图像层面重叠 0）。当前证据支持该框架在 V-SIGHT-Bench 的 13 个上游模型上有效，不支持推广到其他 benchmark 的结论。
