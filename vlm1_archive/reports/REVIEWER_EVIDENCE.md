## W2｜"专用模型 94% 正例定位失败"是我们的坐标口径 bug，不是模型失败

**性质：已确认实现缺陷。这是本轮最重要的发现，必须改写论文。**

### 证据链

审稿人要求区分"语义能力不足"与"接口／几何输出不兼容"。逐样本追查原始响应后，结论是后者：

1. **两个模型的退化框是独占的**。13 个模型里只有 UniVG-R1（156 个）与 visual-rft（122 个）产生零面积框（零宽 65+29、零高 95+101），其余 11 个模型**全部为 0**。
2. **退化框 100% 来自越界裁剪**。visual-rft 的 122 个退化框中，**122/122（100%）**的原始坐标超出图像边界，例如 `[428, 493, 919, 999]` 落在 640×480 图上；`y` 被裁到 480 后框塌成零高。
3. **原始坐标最大值恰为 1000.0**。UniVG-R1 与 visual-rft 的 `<answer>` 坐标上界精确等于 1000，且分别有 **96%**、**96%** 的框超出图像边界 —— 这是 **0–1000 归一化坐标被当作像素读取**。
4. **按 /1000 反归一化后成绩回到中游**：

| 模型 | 论文口径 acc50 | 按像素读 | **按 /1000 反归一化** |
|---|---|---|---|
| UniVG-R1 | **6.0%**（30/500） | 0.4% | **50.8%**（254/500） |
| visual-rft | **5.2%**（26/500） | 0.2% | **42.2%**（211/500） |

5. **这不是"所有模型都这样"，而是这两个模型漏了处理**。全 13 模型扫描显示 4 个模型输出 0–1000 归一化坐标（maxRaw = 1000、越界率 95–97%）：

| 模型 | maxRaw | 越界率 | 流水线 acc50 | /1000 读数 | 结论 |
|---|---|---|---|---|---|
| InternVL3.5-8B | 1000 | 95% | 46.8% | 46.8% | 流水线**已正确**反归一化 |
| Qwen3-VL-8B | 1000 | 97% | 47.6% | 47.6% | 流水线**已正确**反归一化 |
| UniVG-R1 | 1000 | 96% | **6.0%** | **50.8%** | **漏做反归一化** |
| visual-rft | 1000 | 96% | **5.2%** | **42.2%** | **漏做反归一化** |

其余 9 个模型输出像素坐标（maxRaw 644–896），流水线读数与像素读数一致，不受影响。

### 对论文的影响

- 摘要与 §4.3 的"专用模型至少 94% 正例定位失败"**不能保留**。改写后这两个模型的定位成功率为 50.8% / 42.2%，落在其余模型 26.2%–55.0% 的区间内，不再构成"能力崩溃"。
- 表 2、表 4（CBR）、图 2 中这两个模型的全部数值需在修正坐标后重算，其 `n_c` 将从 30 / 26 上升到约 254 / 211，**"小 n_c 估计不稳"这条限制随之消失**。
- 审稿人担心的另一种解释（模型真实泛化失败）**不成立**：同一份原始响应，只改坐标解释就从 0.4% 跳到 50.8%，模型显然找对了区域。
- 论文 group A（"定位大面积失败"）在修正后**只剩 0 个成员**，A/B 分组叙事需要重写。

rescale_fix.json                   # 两个模型全部 t2 行的反归一化框与新 IoU

## W1｜路由依赖评测元数据，已改为只读 query 文本；缓释数字必须重报

**性质：已确认实现缺陷，已修复并重跑采集。**

### 问题

原采集的路由条件是：

```python
if not (ht == 'relation' or role == 'positive'):   # ht = hallucination_type
    continue
```

`hallucination_type` 与 `query_role` 都是**评测标签**，推理时不可得。审稿人指出这使策略无法部署，判断正确。

### 修复

改为审稿人要求的 `route(query, fixed_config)`：

```python
probes, _ = simple_relations.build(query)          # 只读 query 文本 + 冻结谓词表
comp = [x for x in probes if x['probe_type'] == 'competitive']
if not comp: continue                              # 无合法对立词 -> 旁路，不取空集最大值
```

### 关键后果：非关系类也会被路由

文本路由会命中**所有含空间谓词的 query**，与该行的标注类型无关。例如 `the red chair next to the person` 是 **attribute 负例**，但它含 `next to`，因此合法路由必须探测它：

| 类型 | 被路由覆盖的负例行 | 占比 |
|---|---|---|
| positive | 3604 / 6498 | 55.5% |
| object | 1545 / 6498 | 23.8% |
| co_occurrence | 2115 / 6498 | 32.5% |
| attribute | 2270 / 6498 | 34.9% |
| relation | 3186 / 6498 | 49.0% |

**因此旧报告里"非关系三类 CBR 变化恰为 0.00pp"不是方法性质，而是非法门控的产物。** 合法路由下四类都会变化，那条"严格加法"的说法必须删除。

新增采集量：OMNI 侧 11,870 次、JEV 侧 25,432 次，合计 **37,302 次前向，error = 0**。合并后探针集 25,432 行覆盖 13/13 模型。

### 拟合隔离

所有学习量都在**图像级**两折交叉拟合：`md5(图像名) % 2`，fold A 的行由 fold B 拟合的头与阈值判决、反之亦然。没有任何一行被"见过自己图像标签"的参数评分。JEV 的 LoRA + 标量头训练池与 500-dev **图像重叠 = 0**（2000 训练图 vs 评测图，按 COCO 图像名核对）；温度在训练池内 512 行留出片标定。

## W3｜同 CorrectRetain 预算下，OMNI 探针的收益大幅缩水

**性质：已完成审稿人要求的匹配预算实验。结论不利于论文当前表述。**

### 修正后的结论

1. **在同等定位效用下，对立词探针确实降低关系类错误，而不是"更容易删除"。** 两条线、三个操作点共 6 组比较里，relation FGR 与 relation CBR **全部显著下降**；JEV 线在 0.90 处 relation FGR **−10.54pp 且 13/13 模型全改善**。这直接回答了审稿人 W3 的核心质疑。
2. **先前"ALL FGR 显著变差"是操作点不匹配的假象。** 等实际保留率下，OMNI 线三个点全部不显著，JEV 线在 0.90 不显著、0.85 反而显著改善 −1.25pp。
3. **0.95 是两条线都吃力的操作点**：JEV 线在此处 ALL FGR +6.22pp、attribute CBR +8.42pp 显著变差，且只有 10/13 模型可达。**当前证据不支持在 0.95 保留率下部署探针**；0.90 是两线都稳健的操作点。
4. **相对旧报告的量级必须下调。** 旧（非法门控）报告 relation CBR 增量 −9.17pp，合法路由 + 匹配预算下的真实增量是 **−5.58pp（JEV, 0.90）**；OMNI 线从 −4.02pp 降到 **−2.30pp**。方向稳定，幅度明显小于旧数字。
5. **attribute CBR 是探针的代价项**，在 0.95 与 0.85 显著变差、0.90 不显著。合法路由会命中含空间谓词的 attribute 负例（`the red chair next to the person`），这类行的判决被改动，与旧报告"非关系类恰 0.00pp"的结论相反。
