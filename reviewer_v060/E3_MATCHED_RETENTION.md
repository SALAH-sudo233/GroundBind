## 这份文件为什么存在

`matched_retention.json` 生成时间比 `final_policy.json` **早 38 分钟**，跑的是
`CORRECTION.md` 已撤回的旧策略 `A_all`（池化头、无作用域门）。它从未在当前策略上重跑过。
该文件已改名 `matched_retention_WITHDRAWN_A_all.json`，结论不可引用。

`eval_matched_current.py` 直接 import `eval_paper_tables.build()`，所以 E3 用的就是
主表的当前策略：**单调门**（探针头只能 keep→reject，不能复活）+ **作用域门**（仅在谓词
有真实对立配置时生效）。

## 对照怎么构造

两臂的 target 不能直接对齐 —— 完整臂因结构门多拒关系正例，同 target 下保留率必然更低。
做法是取支持臂 `target=0.95` 的**实际保留率** `r`，再在完整臂的保留率曲线上线性插值到
同一个 `r`。目标点扫描 {0.99, 0.98, …, 0.80}，11 点。仅用 test fold。

13/13 模型落在共同可达区间（旧文件只有 11/13）。

## 两套数字的口径差异 —— 不能混用

**固定 target 0.95（主表工作点，`final_policy.json`）：前三类零回退。**
逐模型逐类核对 13×3 = 39 个单元：

- 前三类 CBR：改善 7 / 不变 32 / **变差 0**
- 前三类 FGR：改善 20 / 不变 19 / **变差 0**

这是作用域门的直接后果 —— 不在作用域内的行走 `keep_sup(r)`，逐位沿用支持判决，
结构门碰不到非关系候选。t4 联合定位上同样成立（四类 0/13 变差，`strict_additive` 通过）。

**同保留对照下前三类 CBR 上升，是对照构造的伪影，不是结构门的副作用。**
支持门阈值 `t_sup` 由 `target` 决定。要让完整臂的保留率回到支持臂 `0.95` 的水平，
等效于给完整臂一个更松的 target：

| 模型 | 支持臂 @0.95 实际保留 | 完整臂需 target |
|---|---|---|
| InternVL3.5-8B | 0.9487 | 0.9733 |
| LENS | 0.9395 | 0.9750 |
| Orsta-7B | 0.9404 | 0.9900 |
| Qwen3-VL-8B | 0.9454 | 0.9825 |
| Seg-R1 | 0.9540 | 0.9850 |
| Seg-zero | 0.9382 | 0.9600 |
| TreeVGR | 0.9466 | 0.9900 |
| UniVG-R1 | 0.9449 | 0.9567 |

平均需放松到 **0.9738**（+0.0238）。支持门随之变松，非关系候选少拒 → 前三类 CBR 上升。
归因在更松的**支持门**，不在结构门。

## 结论

结构证据的独立判别力集中在 **relation**：同保留下 FGR −7.88pp、CBR −5.15pp，
CI 均不含 0，13/13 零回退。

整体 ALL FGR 在同保留下 **+0.16pp，CI 跨零不显著** —— relation 仅占负例约 1/4，
relation 上的增益被另三类稀释。主表 ALL FGR −3.39pp 中，超出 relation 贡献的部分
来自更强的拒绝（更低的保留率），不是结构证据的额外判别力。

两条都如实报告：relation 上是真增量，整体 FGR 没有同保留增益。
